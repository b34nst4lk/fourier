## 0. Product definition

A purely-frontend, one-page app that teaches *and demonstrates* how a drawing
is generated by summing rotating circles (Fourier epicycles):

1. **Panel 1 — Sketch pad** (top-left): user places/moves/deletes dots; a
   closed polyline through them forms a shape.
2. **Panel 2 — Output** (top-right): the 1D complex DFT of that closed path,
   rendered as an animated chain of rotating circles (epicycles) whose tip
   traces the reconstruction, plus a static "final frame" mode.
3. **Panel 3 — Term list** (bottom row, full width): the DFT terms that
   generate the reconstruction — read-only rows of (k, radius, phase) with a
   per-row sine sparkline.

Naming & layout: both phases live under one umbrella folder
`workspace/projects/fourier/` (user-ruled "core folder" decision):

    fourier/
    ├── fourier_sketch/   phase 1 — this repo (sketch -> epicycles app)
    └── fourier_toy/      phase 2 — tuning puzzle; consumes the math core

`fourier_sketch` is its own git repo; the umbrella folder itself is not
versioned. Original grilling names kept: `fourier_sketch` (phase 1),
`fourier_toy` (phase 2) — see §7.

## 2. Architecture

- **Target:** Gleam → JavaScript only. This dev machine has **no Erlang**, so
  every build/test/run command MUST pass `--target javascript`.
  - build: `gleam build --target javascript`
  - test: `gleam test --target javascript`
- **Framework:** Lustre for state/app shell; panel 1 is declarative SVG.
- **CI:** runs the JavaScript target (`gleam test --target javascript`);
  `actions/checkout@v7` verified current during the phase-3 review.
- **FFI line:** all math, state, and logic in pure Gleam. JS FFI owns only:
  canvas 2D operations, the `requestAnimationFrame` loop, localStorage access.
- **Rendering split:** panels 1 & 3 are SVG/DOM driven by Lustre; panel 2 is a
  `<canvas>` drawn imperatively through the FFI each RAF tick.

## 3. Math conventions (the contract the tests encode)

- A 2D point `(x, y)` is the complex number `x + iy`. The closed path is
  traversed once per period in dot order.
- **Forward DFT:** `c_k = (1/N) Σ_n p_n · e^{−2πikn/N}`, k over all N samples
  folded to **signed k** in `−N/2 < k ≤ N/2` (negative k = clockwise spin).
- **Inverse/reconstruction:** `p(t) = Σ_k c_k · e^{+2πikt}`; epicycles are the
  chain of vectors `c_k·e^{2πikt}` tip-to-tail; the tip traces the drawing.
- **y-axis mirror:** requirement — panel 2's trace matches the sketch's
  orientation. Mechanism: **none needed** — the browser canvas y-axis also
  grows downward, so complex-plane (re, im) plotted directly as (x, y)
  reproduces the sketch exactly. (The classic epicycle-mirroring bug exists
  only with y-up drawing maths; recorded so nobody "fixes" it back in.)
- **Round-trip identity:** forward→inverse reproduces the samples to < 1e−9.
- **Discrete Parseval:** `Σ|p_n|² = N · Σ|c_k|²` (tested as an invariant).
- Resampler guarantees: output length = n; first sample = first dot; gaps
  equal within 1e−6 of perimeter/n; degenerate inputs (all dots identical,
  single dot) return flat lists, never NaN.

## 4. UI spec

- 2×2 CSS grid; `min ~900px` breakpoints: bottom row may wrap below on narrow
  screens. Dark-only palette (traces glow on dark); colors hardcoded.
- Panel 1: SVG `<circle>` per dot + single closed `<path>`; hover affordance +
  delete affordance (`✕` or alt-click, decided at implementation); cursor hints.
- Panel 2 toolbar: play/pause, final-frame toggle, circles slider (4–256)
  with live count label. Animation restarts on sketch change.
- Panel 3: table columns `k | radius | phase | waveform`; amplitude-descending
  sort; slider-cut rows dimmed; all computed terms shown (up to 256).
- Empty states: panels 2–3 rendered as quiet hints until ≥3 dots exist.
- Autosave: on every model mutation, `localStorage["fourier_sketch/v1"]`;
  schema version byte; corrupt/absent → presets fallback.

## 5. Quality gates

- **Property/unit tests** (gleeunit, JS target): complex identities; resampler
  guarantees; DFT known inputs (zero, constant=DC, pure circles ±1); round-trip
  < 1e−9; Parseval; term sort/slice; undo stack invariants; store round-trip.
- **Perf budget:** resample+forward+sort pipeline at worst case (60 dots,
  N=512, all terms) **≤ 8 ms/frame** on Node, published to README. Bench: a
  `main` module timing the pipeline over a worst-case fixture (phase 7).
- **Smoke checklist** (manual, in README): spam-click, drag storm, slider
  thrash, clear→undo loops, resize mid-animation, restore-from-corrupt.

## 7. Phase-2 shelf (parked — NOT in this repo's scope)

`fourier_toy` — a tuning puzzle: players adjust term configurations to
approximate a target shape, scored by pointwise path distance over the period.

- Core mode: **radius + phase sliders, k locked** (orthogonality ⇒ per-term
  ground truth = the true DFT coefficient).
- Hard mode (later): **choose which frequencies** from a pool (k tunable).
- Scoring: sample both curves at the same phase points; mean/RMS distance,
  normalized.
- Wants from `fourier_sketch`: the math core package (complex, resample, dft,
  terms), plus a shareable JSON export format (parked until now).
